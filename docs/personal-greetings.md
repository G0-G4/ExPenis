# Персональные поздравления

Владелец сервера может назначить пользователю короткое сообщение. Оно появляется
над списком транзакций в веб- и мобильном приложении. Пользователь закрывает его
кнопкой «Close greeting»; закрытие хранится на сервере и учитывается на других
устройствах при следующей загрузке сообщения.

Команды запускаются в корне репозитория на сервере с доступом к рабочей БД.
При нестандартном пути укажите `EXPENIS_DB_PATH`. Назначать сообщения через
пользовательский API нельзя; роль администратора в приложении не требуется.

## Команды

```bash
# Назначить по username; текст может содержать эмодзи.
uv run -m src.expenis.server greeting set --username alice --text 'С днём рождения! 🎉'

# Назначить по ID, в том числе пользователю без username.
uv run -m src.expenis.server greeting set --user-id 42 --text 'Спасибо, что ты с нами!'

# Многострочный текст: один аргумент shell.
uv run -m src.expenis.server greeting set --username alice --text 'Поздравляю! 🎉
Пусть всё получится!'

# Показывать до конца указанной даты включительно по Москве.
uv run -m src.expenis.server greeting set --username alice --text 'С Новым годом!' --expires-on 2026-12-31

# Посмотреть сообщение, ID назначения, срок и состояние.
uv run -m src.expenis.server greeting show --username alice
uv run -m src.expenis.server greeting show --all

# Удалить сообщение, включая уже закрытое или истёкшее.
uv run -m src.expenis.server greeting delete --user-id 42

# Назначить или удалить у всех существующих пользователей.
uv run -m src.expenis.server greeting set --all --text 'С праздником! 🎉'
uv run -m src.expenis.server greeting delete --all

uv run -m src.expenis.server greeting --help
uv run -m src.expenis.server greeting set --help
```

На пользователя хранится одно сообщение. Новое назначение заменяет старое и
снова показывает блок, даже если текст не изменился. Истории и отмены замены нет.
Допустим обычный непустой текст длиной до 1000 Unicode code points; переносы и
эмодзи сохраняются. Markdown и картинки не поддерживаются.

Без `--expires-on` сообщение остаётся до закрытия, удаления или замены. Срок
указывается как `YYYY-MM-DD`: сообщение с датой `2026-12-31` исчезнет в
`2027-01-01 00:00:00 Europe/Moscow`. Прошедшая московская дата недопустима.
На экране срок не зависит от даты выбранных транзакций.

Массовые назначение и удаление выводят количество получателей и требуют ответа
`y` или `yes`. Отказ, пустой ответ или недоступный ввод отменяют операцию. При
нулевой выборке подтверждение не запрашивается. Список получателей фиксируется
до подтверждения; зарегистрировавшиеся после этого пользователи не получают
сообщение. Все изменения выбранного набора выполняются одной транзакцией.

## Обновление клиентов

Текст и факт закрытия загружаются при открытии вкладки транзакций, возврате на
неё, возобновлении приложения и нажатии «Refresh». Мгновенной push-синхронизации
нет. После закрытия сообщения новое назначение снова будет показано.

Ошибка чтения сообщения показывает «Could not load greeting» с кнопкой «Retry»,
не блокируя транзакции. При ошибке закрытия текст остаётся, действие можно
повторить. Длинный текст прокручивается внутри блока; кнопка закрытия доступна
независимо от прокрутки.

## Развёртывание и откат

Перед запуском нового backend примените новую миграцию к существующей БД
(один раз; предыдущие миграции уже должны быть применены):

```bash
sqlite3 "${EXPENIS_DB_PATH:-./data/expenis.db}" < migrations/009_personal_greetings.sql
```

Затем обновите backend и только после этого frontend; команды развёртывания
описаны в [deployment.md](deployment.md). До первого назначения у пользователей сообщений нет.
Старые клиенты совместимы с новым backend, но не показывают сообщения.

При откате верните предыдущий frontend перед backend. Новую таблицу можно
оставить неиспользуемой; автоматического удаления сообщений при откате нет.
Не редактируйте уже применённые миграции.
