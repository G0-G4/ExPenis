## Context

Мотивация и согласованный объём — в `proposal.md`; наблюдаемое поведение — в `specs/transaction-export/spec.md`.

- `get_transactions_for_period` в `src/expenis/core/service/transaction_service.py` требует обе границы периода; существующий `GET /api/transactions` возвращает DTO, в котором нет сохранённого курса.
- `get_user_accounts` в `account_service.py` скрывает мягко удалённые счета, хотя операции и связи с ними сохраняются. Баланс дополнительно зависит от `adjustment_amount`, поэтому экспорт истории не восстанавливает остатки.
- `created_at` допускает наивные datetime и строки со смещением. Flutter обычно отправляет локальное время без смещения; нормализация всей истории в UTC изменила бы смысл дат.
- Деньги и курсы хранятся как float. Направление задаёт категория; положительность суммы не гарантирована. Теги плоские, для них уже есть пакетная загрузка по ID операций.
- Flutter использует общий Dio с Bearer и refresh/retry, причём `validateStatus` принимает 4xx. Есть `path_provider`, но общего сохранения файлов нет. Настройки находятся в `settings_screen.dart`.

## Goals / Non-Goals

**Goals:**
- Одна авторизованная выборка и единое представление строки для обоих сериализаторов.
- Сохранение исторических значений без вызовов сервиса актуальных курсов и без изменений данных.
- Изоляция HTTP, формирования файлов и платформенного сохранения по существующим слоям.
- Обратная совместимость существующих endpoint и моделей.

**Non-Goals:**
- Исправление всей модели времени и переход денежных полей на Decimal.
- Новый менеджер состояния Flutter, фоновые задания экспорта, постоянное хранение файлов или публичные ссылки.
- Изменение обычного списка счетов, аналитики или способа расчёта баланса.

## Decisions

### 1. Специализированный API экспорта

Добавить два маршрута с Bearer-авторизацией:

- `GET /api/exports/accounts`, operationId `listExportAccounts`: `{accounts: [{id, name, currency_code, is_deleted}]}` только для текущего пользователя, включая мягко удалённые счета. Имя передаётся исходным, UI добавляет отметку удаления. Балансы не вычисляются.
- `GET /api/exports/transactions`, operationId `exportTransactions`: обязательный `format=csv|xlsx`, необязательная пара `date_from`/`date_to` (`YYYY-MM-DD`) и повторяемый `account_ids`. Отсутствие IDs означает все счета; явный список обязан содержать хотя бы один ID. Дубликаты IDs устраняются. Пустые/некорректные значения, неполная пара дат, обратный период и неизвестный формат дают 422. Чужие и несуществующие счета дают одинаковый 404, весь запрос отклоняется.

Ответ: `text/csv; charset=utf-8` либо `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `Content-Disposition: attachment` с ASCII-именем `ExPenis-transactions.csv|xlsx`, `Cache-Control: no-store`. При отсутствии авторизации — существующее поведение auth-слоя без файлового ответа. В OpenAPI документировать оба бинарных ответа, параметры, ошибки и русские описания.

Альтернативы: расширять обычный список транзакций и формировать файлы во Flutter либо добавлять `include_deleted` к обычному API счетов. Отдельные маршруты сохраняют поведение существующих клиентов и не вынуждают переносить курс/правила форматов в каждый клиент. Маршруты `/api/exports/...` не конфликтуют с `/api/transactions/{transaction_id}`.

### 2. Данные и сериализаторы в core/service

Создать `transaction_export_service.py` с типизированным фильтром и неизменяемой моделью строки. Сервис проверяет владение выбранными счетами, выбирает операции с явным `Transaction.user_id == user_id`, загружает счета/категории и теги пакетно. Список счетов также явно ограничен `user_id`. Для фильтра «Все счета» не использовать список активных счетов как разрешающий набор.

Выборка сортируется по сохранённой дате/времени и ID по возрастанию. Сравнение периода должно опираться на сохранённую календарную дату без SQLite-преобразования смещения в UTC: например, ISO-префикс даты при поддерживаемом формате хранения. Покрыть наивное время и время со смещением тестами. Существующую выборку аналитики не менять.

Рендеринг в отдельном модуле сериализации использует общий порядок десяти колонок из спецификации. Категории и счета выгружаются под текущими сохранёнными названиями, исторических версий названий в БД нет. К имени удалённого счёта добавляется «(удалён)». Пустой комментарий становится пустой строкой; теги сортируются стабильно и сериализуются `json.dumps(..., ensure_ascii=False)`. Исходная сумма и сохранённый курс используются непосредственно; сумма в рублях вычисляется их произведением. Экранное округление и дополнительный множитель направления не применяются.

Альтернатива — переиспользовать API DTO. Она отвергнута: DTO не содержит курса, а транспортные преобразования не должны становиться зависимостью core.

### 3. CSV стандартной библиотекой, XLSX через XlsxWriter

CSV формируется `csv.writer` с разделителем-запятой, двойными кавычками, CRLF и UTF-8 BOM ровно один раз. Числа — независимое от локали представление исходного float без группировки и дополнительного округления; время — ISO 8601. Наивному времени не приписывать UTC; имеющееся смещение оставлять в CSV.

XLSX записывать через XlsxWriter в режиме последовательной записи `constant_memory`; новая production-зависимость оправдана обязательным форматом XLSX. Текст писать явно как строки, без определения формул и URL; числа — числовыми ячейками. Использовать один лист «Операции», формат даты с секундами и читаемые ширины колонок. Для timezone-aware datetime удалить только `tzinfo`, без `astimezone`: Excel хранит календарные компоненты, а не смещение. Проверять пределы строк/длины ячейки и ошибки записи; при превышении вернуть понятную ошибку (422), не обрезанный файл. Автофильтр, формулы и итоги не нужны.

Альтернативы: pandas добавляет ненужную тяжёлую зависимость; самостоятельная сборка OOXML усложняет поддержку; сериализация на клиенте дублирует правила форматов. Проверенные источники: [XlsxWriter memory](https://xlsxwriter.readthedocs.io/working_with_memory.html), [ограничение timezone](https://xlsxwriter.readthedocs.io/workbook.html), [типизированные записи](https://xlsxwriter.readthedocs.io/worksheet.html).

### 4. Временный файл и явные ошибки

Полностью завершить формирование файла до выдачи HTTP 200, чтобы ошибка XLSX не выглядела успешной частичной загрузкой. Запись выполняется вне event loop после асинхронной загрузки данных, результат хранится во временном файле. HTTP-слой отдаёт его и удаляет после передачи; исключения и отмены также освобождают ресурс. Не хранить файлы в публичной директории, не логировать содержимое операций и токены.

Первая версия может материализовать выбранные строки в памяти, как текущий API операций; рендеринг XLSX с `constant_memory` и файл на диске уменьшают дополнительные копии. Не вводить скрытый лимит числа операций. Измерить время и память на большой тестовой истории; при необходимости пакетная загрузка может заменить материализацию, не меняя контракт API. Фоновая очередь заданий сейчас не оправдана.

### 5. Форма экспорта и получение файла во Flutter

Из настроек открыть отдельный экран. Локальное состояние через `setState`: режим всего периода или две даты, режим всех счетов или явный набор ID, формат (CSV по умолчанию), загрузка/ошибка. Каталог счетов получает новый endpoint; удалённые видимы и выбираемы. Пустой явный выбор блокирует кнопку, при отсутствии счетов режим «Все счета» позволяет выгрузить пустую историю. Не сохранять настройки формы между открытиями — это небольшой дефолт первой версии.

HTTP-сервис наследует `BaseService`, запрашивает байты через общий Dio, сохраняет Bearer и refresh/retry. Проверять statusCode и Content-Type до передачи платформенному слою: из-за `validateStatus` нельзя полагаться только на DioException. Для ошибок в byte-response разбирать JSON detail, не сохранять его в файл. При отсутствии доступного Content-Disposition использовать фиксированное имя по выбранному формату, не расширять CORS только ради имени.

Платформенный сервис возвращает результат «передан/сохранён», «отменён» либо ошибку; он не использует BuildContext. UI не утверждает, что share-диалог гарантирует сохранение. Повторный запуск во время запроса блокируется; ошибки сохраняют фильтры. После await проверять mounted.

| Платформа | Получение файла |
| --- | --- |
| Web | Blob/object URL и браузерное скачивание через условный web-модуль, затем освобождение URL |
| Android/iOS | Временный файл и системное меню через share_plus; на iPad передавать anchor; очищать временные файлы после безопасного завершения передачи/при следующем запуске |
| Linux/macOS/Windows | Диалог сохранения через file_selector, запись в выбранное место; отмена без ошибки; macOS entitlement для выбранного пользователем файла |

Добавить только необходимые плагины и их требуемые настройки, совместимые с текущим toolchain. Версии зафиксировать при apply после проверки ограничений SDK. Выбор нескольких механизмов обоснован матрицами поддержки: [file_selector](https://pub.dev/packages/file_selector) не выбирает место сохранения на mobile/web; [share_plus](https://pub.dev/packages/share_plus) не передаёт файлы на Linux. Прямое открытие URL API не подходит из-за Bearer-авторизации; использование APK installer для других файлов не подходит по назначению.

### 6. Принятые небольшие допущения

Зафиксированы для реализации: CSV как начальный формат, старые операции первыми с ID как вторым ключом, фиксированное имя файла, файл только с заголовками при пустой выборке, отсутствие постоянного хранения фильтров и отсутствие дополнительных ID-колонок. Это не расширяет согласованные цели. Проверка переноса в конкретное стороннее приложение не является критерием приёмки.

## Risks / Trade-offs

- [Неоднозначная историческая timezone-семантика] → сохранять календарные компоненты; не нормализовать данные в рамках экспорта; CSV сохраняет имеющееся смещение, XLSX его не представляет.
- [Float и Excel имеют ограничения точности] → не вводить экранное округление, тестировать реальные значения; экспорт не обещает точности, которой нет в исходном хранилище.
- [CSV не задаёт тип текстовой ячейки; редактор может распознать формулу] → сохранять CSV как переносимые исходные данные, не добавлять меняющие значения апострофы; XLSX явно записывает текстовые типы. CSV предназначен для импорта с сопоставлением полей, XLSX — для открытия в таблицах.
- [Большая история требует памяти/времени, XLSX имеет пределы] → временный файл, неблокирующий рендеринг, измерение на большой истории, явная ошибка без обрезки и возможность выбрать CSV/сузить период.
- [Плагин поддерживает платформу, но не конкретный save/share API] → отдельная матрица выше и нативные smoke-проверки; unit-тесты не доказывают работу системных диалогов.
- [Название/валюта счёта и категория берутся из текущих связанных сущностей] → не обещать исторические названия или реконструкцию старого состояния приложения.

## Migration Plan

1. При apply добавить backend-зависимость, сервис, маршруты и тесты; повысить backend minor-версию, поскольку API расширяется; выполнить `just lock` и `just openapi`.
2. Добавить Flutter-форму, получение файлов и зависимости, обновить Flutter lockfile и настройки платформ. Миграций SQLite нет.
3. Прогнать целевые проверки, backend suite и Flutter analyze/test; проверить реальные файлы и платформенное получение. Сначала развернуть backend, затем совместимый frontend через обычный процесс проекта. Публикация релиза и deploy не входят в этот change.
4. Откат: вернуть frontend и backend к предыдущим версиям обычным процессом. Экспорт ничего не пишет в доменные данные, поэтому обратная миграция БД не требуется.
