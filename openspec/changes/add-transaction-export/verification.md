# Проверка экспорта операций

Изменение `add-transaction-export`, задача GitHub #26. Работа выполнена в отдельной рабочей копии `issue-26-grilling/expenis`. Реализация подготовлена; Android проверен на реальном Pixel 6a. OpenSpec остаётся открытым до завершения iOS и desktop-проверок (оставшиеся части задач 3.3, 3.4 и 5.3).

## Реализовано

- Авторизованные `GET /api/exports/accounts` и `GET /api/exports/transactions`.
- Собственные активные и удалённые счета; вся история или включительный период по сохранённой календарной дате, выбранные счета, стабильная сортировка.
- Общая таблица из десяти русских колонок, CSV UTF-8 BOM, XLSX с одним листом и типизированными ячейками; сохранённый курс, исходный знак и JSON-теги.
- Временные файлы backend очищаются при завершении ответа, ошибке и отмене; рендеринг выполняется вне event loop.
- Настройки → «Экспорт операций», проверка фильтров, закреплённая кнопка, ошибки с повтором, отсутствие повторного запроса во время подготовки.
- Скачивание web, системная передача Android/iOS, системный save-диалог desktop, отмена; просроченные временные файлы mobile удаляются при запуске приложения и перед очередной передачей. Недавние файлы сохраняются на сутки для асинхронного чтения принимающим приложением.
- Backend-версия 1.3.0; существующие пути и схемы OpenAPI сравнены с HEAD и не изменены. Frontend-версия и release-публикация не затрагивались.

## Browser e2e

Команда (из корня):

```sh
E2E_API_URL=http://127.0.0.1:8260 E2E_BASE_URL=http://127.0.0.1:8261 uv run --group e2e pytest e2e/test_export.py --browser-channel chrome -q
```

Результат: **1 passed**. Использованы отдельная временная SQLite БД `/private/tmp/expenis-export-26/smoke.db`, backend :8260 и debug web :8261 с `EXPENIS_API_BASE_URL=http://127.0.0.1:8260`. Рабочая dev БД и другие стеки не затрагивались.

Сценарий создаёт тестового пользователя, активный и удалённый счета, операции 2000 года и текущего месяца, отрицательную сумму, кириллицу/эмодзи, кавычки/перевод строки в комментарии, теги с запятой/кавычками. Через UI выполняются вход, переход из настроек, скачивание CSV/XLSX целиком, затем за выбранный период и только по удалённому счёту. Скачанные файлы читаются CSV/XML-парсерами: сверены строки, колонки, исходные суммы, сохранённый курс, рубли, тексты и теги. Затем имитируется HTTP 422: JSON не скачивается, ошибка видна, повтор получает корректный XLSX с прежними фильтрами.

В проверке исправлены перекрытие ошибки предыдущим success snackbar и нестабильная доступность кнопки в длинной форме. Кнопка и сообщение теперь находятся в нижней области формы; ошибка объявляется через live region.

Screenshot-артефакты этой сессии: `/private/tmp/expenis-export-26/export-screen.png`, `export-mobile.png` (390×844) и `export-error.png`. Это локальные временные файлы, не содержимое production-аккаунта.

| macOS | Debug app собран | Настоящий save-диалог и отмена не проверены: CUA вернул `Computer Use permissions are not granted` |
| Android | Debug APK собран; на Pixel 6a / Android 17 проверены share-диалог, отмена/повтор, получение CSV/XLSX другим процессом и сохранение в Downloads | Нет для проверенных сценариев на этом устройстве |

Android первоначально не собирался под Java 25.0.2; с JDK 17 обнаружено исходное требование Gradle к `android/key.properties` даже для debug. Для проверки использован временный игнорируемый конфиг с нерабочими release-заглушками; debug использует стандартную debug-подпись. Конфиг удалён, реальные release-ключи не читались. Для последующей проверки телефона собран и установлен отдельный пакет `ru.g0g4.expenis.exportcheck`; основной пакет приложения не переустанавливался. Изменений конфигурации подписи в исходном коде нет.

Тесты адаптеров подтверждают байты/имя/MIME, iPad anchor, реальную запись во временное выбранное место, отмену, ошибки записи/передачи и очистку файлов. Они **не заменяют** системные диалоги на устройствах. Android-часть пунктов 3.3 и 5.3 теперь подтверждена на устройстве; сами пункты 3.3, 3.4 и 5.3 остаются незавершёнными из-за iOS/desktop; разрешение на изменение требований или исключение этих проверок не предполагалось.

## Проверка реального Android-телефона

Проверен Pixel 6a с Android 17 по USB через ADB. Временная сборка «ExPenis Export Check» использовала тот же Dart-код, что рабочая копия (сравнение `frontend/lib` не выявило отличий), отдельный applicationId и тестовый API `127.0.0.1:8270` через USB reverse. В изолированной копии Android-конфигурации изменены только ID/название, разрешение debug HTTP и удержание экрана включённым во время проверки; основной исходный код Android не менялся. Данные созданы в отдельной временной `phone.db`: три синтетические операции, включая удалённый счёт, отрицательную сумму и сложные строки/теги.

Проверено на устройстве:

1. Вход в тестовую учётную запись, переход Settings → «Экспорт операций».
2. Для CSV — настоящий системный chooser с именем `ExPenis-transactions.csv`, отмена, возврат к форме с доступной кнопкой и без ложного success-сообщения, повторный экспорт.
3. Передача файла отдельному локальному тестовому приёмнику `ru.g0g4.expenis.exportreceiver`. Приёмник не имеет сетевых разрешений: читает выданный Android content URI через ContentResolver, фиксирует MIME/имя/размер/SHA-256 и открывает стандартный ACTION_CREATE_DOCUMENT.
4. Сохранение через системный DocumentsUI в Downloads; полученный CSV прочитан обратно через USB.
5. Переключение в XLSX, отмена и повтор с сохранением выбранного формата; получение URI другим процессом и сохранение в Downloads тем же способом.
6. Оба сохранённых файла имеют те же SHA-256, что байты, прочитанные принимающим процессом. CSV и XLSX содержат 3 операции / 10 колонок; проверены знак, сохранённый курс, рубли, удалённый счёт, теги, кириллица, кавычки и перевод строки. XLSX содержит один лист «Операции», числовые суммы/курс/дату и текст вместо формулы.
7. После передачи приложение возвращается к рабочей форме, кнопка экспорта доступна.

| Файл в Downloads | Размер | Результат |
| --- | --- | --- |
| `ExPenis-phone-check-csv.csv` | 696 байт | Получен через Android URI, сохранён и содержимое проверено |
| `ExPenis-phone-check-xlsx.xlsx` | 5585 байт | Получен через Android URI, сохранён и содержимое проверено |

Это проверка реального межпроцессного получения файла, разрешения на URI и системного сохранения, а не mock платформенного адаптера. Локальный тестовый приёмник используется как получатель из системного share-меню; наличие встроенного пункта «Сохранить в файлы» у остальных установленных приложений не предполагается. Передача в личные мессенджеры и облака не выполнялась. Произвольные сторонние получатели отдельно не проверялись.

Сырые результаты — `android-phone-verification.json`. Артефакты с синтетическими данными находятся в `/private/tmp/expenis-export-phone/`: `saved.csv`, `saved.xlsx`, `csv-saved.png`, `xlsx-saved.png`, `phone-final.png`. Два тестовых файла оставлены в Downloads телефона для просмотра; временные тестовые пакеты удалены после проверки. USB reverse для порта 8270 удалён, тестовый backend остановлен; существующий reverse порта 8000 сохранён.
