## Why

Пользователь не может выгрузить историю ExPenis для самостоятельного анализа или переноса в другое приложение. Задача [#26](https://github.com/G0-G4/ExPenis/issues/26) добавляет переносимую таблицу операций в CSV и XLSX с сохранением исходных финансовых данных.

## What Changes

- Добавить в настройки пункт «Экспорт операций» с выбором периода, счетов и формата CSV/XLSX.
- По умолчанию выгружать всю историю всех счетов, включая удалённые; поддержать включительные границы периода, без фильтров категорий и тегов.
- В обоих форматах использовать одинаковые русские колонки: дата и время, тип, сумма, валюта, счёт, категория, комментарий, сохранённый курс, сумма в рублях, теги.
- Сохранять исходную сумму без изменения знака, дату/время без пересчёта часового пояса, теги — JSON-списком в одной ячейке.
- CSV: UTF-8 с BOM, запятая между полями, дробная точка, даты ISO. XLSX: один лист «Операции», числовые суммы и ячейки даты/времени, без итоговых строк.
- Обеспечить скачивание в браузере и системное сохранение/передачу на нативных платформах.
- Не включать импорт, QIF/OFX, резервное копирование, восстановление остатков или гарантированную совместимость с конкретным сторонним приложением.

## Capabilities

### New Capabilities

- `transaction-export`: выбор и безопасная выгрузка собственной истории операций в CSV/XLSX, общий контракт данных и получение файла на поддерживаемых платформах.

### Modified Capabilities

Нет. Существующие требования аналитики, тегов и мониторинга не меняются.

## Impact

- Backend: новый авторизованный API экспорта и получение списка доступных для экспорта счетов, включая удалённые; выборка и формирование строк в core/service, тонкие HTTP-обработчики.
- Flutter: настройки, форма экспорта, HTTP-сервис и платформенный слой получения файла с текущим механизмом обновления токенов.
- Потребуются библиотека записи XLSX на backend и минимальные платформенные зависимости сохранения/передачи файла; CSV формируется стандартной библиотекой Python.
- Обновить backend-версию и `docs/openapi.json` при реализации нового API, добавить проверки выборки, обоих файлов и пользовательского сценария. Изменения схемы БД не требуются.
