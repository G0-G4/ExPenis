# Проверка add-amount-expressions

Дата: 2026-11-21.

## Вычислитель, поле и формы

- `flutter test --no-pub`: 80 тестов прошли, включая новые unit-, widget- и тесты форм с контролируемыми HTTP-ответами.
- После финального оформления строк отдельно повторены `test/amount_expression_test.dart`: 4 теста прошли.
- `flutter analyze --no-pub`: замечаний нет.
- `dart format --output=none --set-exit-if-changed` для 9 изменённых Dart-файлов: изменений нет.
- Проверены приоритет операций, скобки, унарные знаки, точка/запятая, варианты символов операций, отсутствие промежуточного округления, половины копейки обоих знаков, ноль, отрицательные суммы, ошибки/лимиты и преобразование в API-число.
- Проверены все формы: создание/редактирование операции, начальный баланс и изменение итогового баланса. Запросы содержат округлённое число; неверный ввод не вызывает запись. После ошибки сети выражение остаётся для повторной отправки. Повторное открытие показывает числовую сумму.
- Widget-тесты проверяют ввод у каретки, выделение и удаление, Meta+A на macOS, сохранение фокуса, Done, Back, переход к описанию, resize и альбомную ориентацию с масштабом текста 2.

## Браузер

Локальный debug Flutter web (`flutter run -d web-server`) и backend на loopback с отдельной временной SQLite-БД, созданной из миграций. Рабочая `data/expenis.db` не используется.

- Сценарий создания счёта с `1000/3` и расхода с `40+5/2` проверяет реальные значения: начальный баланс `333.33`, расход `42.50`, итоговый баланс `290.83`. Повторное открытие операции показывает `42.5` вместо выражения.
- Телефонная компоновка Chrome: 390×844 и 844×390. Проверяются кнопочный ввод, выделение/замена с физической клавиатуры, деление на ноль и исправление, удаление, видимость preview над панелью, Done без submit и переход к обычному текстовому полю.
- Скриншоты `calculator-portrait.png` и `calculator-landscape.png` создаются в `tmp_path` e2e-теста. Оба варианта визуально просмотрены: поле и результат не перекрываются клавиатурой.
- В ходе проверки исправлен перехват браузерного фокуса обычными кнопками: клавиши используют `InkWell(canRequestFocus: false)` и остаются доступными через семантику кнопок. Одного сохранения Flutter-фокуса недостаточно: браузер использует DOM-фокус для нативных сочетаний выделения. E2e проверяет реальный путь браузера.
- Тест выделения ждёт завершения кадра после тапа и подтверждает нативное выделение перед заменой, чтобы сочетание клавиш не обгоняло обработку каретки Flutter.

**Итоговый `just e2e`: 4 теста прошли за 36.15 с.** Отдельный телефонный сценарий после синхронизации также прошёл. Браузер: локальный Chrome 157 на macOS; это не эмуляция мобильной ОС.

## Непроверенные поверхности

- Настоящий Android: по запросу пользователя на Pixel 6a установлена и запущена отдельная debug-сборка `MyPennies Keyboard` (`ru.g0g4.expenis.keyboardtest`). Запуск подтверждён `am start -W` и наличием процесса. Обновление основного приложения отклонено Android из-за несовпадения подписей; исходная версия и её данные сохранены. Для тестовой сборки запущен изолированный локальный backend и настроен USB reverse порта 8000. Сборка выполнена на Java 17; временные изменения applicationId/названия возвращены. Ручная проверка самой клавиатуры пока ожидает пользователя, установка и запуск не считаются её прохождением.
- iOS: подключённого устройства или запущенного симулятора в `flutter devices` нет; ручная проверка не выполнена.
- Chrome с телефонным viewport проверяет адаптивную web-компоновку, но не доказывает отсутствие системной клавиатуры на настоящем Android/iOS, работу мобильной вставки, экранного диктора или удобство ввода одной рукой.
- До закрытия задачи 5.3 нужно проверить эти пункты в Android/iOS и реальном мобильном браузере. Задача оставлена незавершённой; change не архивирован.
