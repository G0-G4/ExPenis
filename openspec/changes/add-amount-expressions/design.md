## Context

Мотивация и охват описаны в `proposal.md`; поведение — в `specs/amount-expression-input/spec.md`.

Три Flutter-экрана независимо используют `TextFormField`, `double.tryParse` для проверки и `double.parse` при сохранении. Создание и редактирование операций используют общий `edit_transaction_screen.dart`; остальные поля находятся в `create_account_screen.dart` и `edit_account_screen.dart`. Суммы представлены `double` во Flutter и `float` в API. Редактирование баланса отправляет желаемый итоговый баланс, а backend вычисляет корректировку. `formatAmount` уже форматирует дробные суммы до двух знаков, но не определяет точность сохранения.

Системные числовые клавиатуры не гарантируют набор арифметических операций. Нужна общая панель для Android, iOS и телефонного web. Дизайн необходим, поскольку изменение затрагивает несколько форм, вычисление и управление фокусом.

## Goals / Non-Goals

**Goals:**
- Один независимый от UI вычислитель и один денежный компонент для всех форм.
- Единое вычисленное значение для предпросмотра, валидации и отправки.
- Сохранить каретку, выделение, вставку и возможность редактировать выражение при использовании собственной клавиатуры.
- Не менять транспортную модель и правила корректировки баланса.

**Non-Goals:**
- Универсальный калькулятор, проценты, степени, функции, переменные, неявное умножение и история выражений.
- Миграция всех денежных данных на decimal, изменения backend и БД.
- Системное расширение клавиатуры, переключение клавиатуры ОС и её настройки.
- Публикация релиза, обновление версий или изменение несвязанных форм.

## Decisions

### 1. Ограниченный парсер и точная арифметика до границы API

Добавить чистый Dart-вычислитель в `frontend/lib/utils/amount_expression.dart` с результатом закрытого набора состояний: корректное значение, незаконченный ввод, синтаксическая ошибка, деление на ноль, превышение допустимых ресурсов/диапазона. Разобрать всё выражение до конца; не выполнять произвольный код.

Грамматика: выражение из сумм/разностей, произведения/частные, унарный знак, число или выражение в скобках. Нормализовать `×`/`÷`/`−` и десятичную запятую. Пробелы пропускать между токенами, но не склеивать `1 2` в `12`. Разрешать `.5`, `,5` и `1.` как числовой ввод; экспоненциальную запись из пользовательского текста не включать в грамматику. Существующие значения при открытии форматировать как обычное десятичное число, совместимое с грамматикой.

Предпочесть простой рекурсивный спуск без новой зависимости: операторов мало, а необходимы разные состояния незаконченного ввода и ошибок. Универсальные библиотеки выражений приносят лишнюю грамматику, `double`-погрешности и не всегда подходящие ошибки.

Десятичные литералы представить рациональными числами на `BigInt` (числитель/знаменатель), выполнять четыре операции точно, сокращая дроби. В конце округлять до целого числа копеек: ближайшее значение, при равенстве — от нуля. Так `1.005` даёт `1.01`, а `1/3*3` даёт `1`; промежуточного округления нет. Только перед отправкой преобразовать итог в существующий `double` и проверить конечность и сохранение точности копеек при обратном округлении. Непредставимый результат отклонять понятной ошибкой. API и хранение остаются приблизительными числами, но эта работа не расширяет их возможности.

Технические ограничения для отзывчивого предпросмотра: до 512 символов и до 32 уровней скобок; превышение возвращает контролируемую ошибку. Это реализационные допущения, не новые пользовательские возможности. Покрыть пределы тестами; не обрезать текст молча.

### 2. Общий денежный компонент

Добавить `AmountExpressionField` в `frontend/lib/widgets/amount_expression_field.dart`. Он использует существующий `TextEditingController`, поддерживает декорацию/подпись/валюту и общий контракт `Form`. Изменения текста пересчитывают состояние вычислителя, не переписывая текст контроллера. Предпросмотр использует `formatAmount` от уже округлённого значения; отрицательный ноль нормализуется.

Предоставить форме типизированный доступ к текущему валидному округлённому значению и признаку допустимости сохранения. Обработчик сохранения повторно проверяет текущее состояние и не использует последний успешный результат при невалидном текущем вводе. Заменить прямые `double.parse` во всех трёх формах; не вычислять выражение разными алгоритмами в UI и submit.

Состояние проверки хранит факт ухода из поля или попытки отправки. До этого синтаксическая ошибка/незаконченный ввод скрывает preview без красного сообщения; деление на ноль видно сразу. После исправления ошибка снимается. Действие сохранения не должно отправлять запрос при неверном поле; если кнопка отключена, уход из поля и Done всё равно должны объяснить причину. Сохранить существующие английские пользовательские строки, добавить сообщения в том же стиле.

Альтернатива — продублировать вычисление и состояние в трёх экранах — отклонена из-за риска разного поведения форм.

### 3. Встроенная клавиатура внизу формы

Добавить общий `AmountCalculatorKeyboard` и механизм размещения панели у нижнего края текущей формы. На телефонной компоновке денежное поле подавляет системную клавиатуру через `TextInputType.none`, оставаясь редактируемым и поддерживая выделение и вставку. Переход в обычное текстовое поле возвращает штатную клавиатуру.

Панель: сетка цифр, десятичный разделитель, `+`, `−`, `×`, `÷`, `(`, `)`, удаление и Done. Операторы находятся в той же сетке, а не отдельной строкой возле поля. Кнопки обновляют `TextEditingController.value`: заменяют выделение или вставляют символ у каретки; удаление работает по выделению или предыдущему символу. Нажатия кнопок не должны уводить фокус из денежного поля. Сохраняются размер зон касания не менее 48 logical pixels, семантические подписи, SafeArea, масштабирование текста и темы приложения.

Done снимает фокус и закрывает панель, не сохраняет форму и не подменяет выражение числом. Back сначала закрывает открытую панель; повторное действие возвращается со страницы по обычным правилам. Тап на другое поле и уход со страницы освобождают панель. Учесть panel height в прокрутке: денежное поле, ошибка и preview остаются видимыми, другие поля и submit достижимы.

Допущение для первой реализации: телефонная компоновка определяется кратчайшей стороной окна менее 600 logical pixels, включая web, и работает в обеих ориентациях. На остальных размерах используется обычный ввод с физической/системной текстовой клавиатуры без принудительной панели калькулятора. Подключённая физическая клавиатура продолжает редактировать поле и при открытой панели. Проверить телефонный web отдельно: один `kIsWeb` не определяет способ ввода.

Альтернативы: системная текстовая клавиатура требует переключения раскладок; отдельная строка операторов отвергнута пользователем. Нативные расширения клавиатуры не дают общей реализации для web и требуют отдельного сопровождения платформ.

### 4. Интеграция без изменения хранения

Формы отправляют только числовую сумму в существующие запросы. После успешного сохранения и повторной загрузки контроллер получает сохранённое число (для счёта — актуальный баланс). Выражение живёт только в локальном состоянии текущей формы. При ошибке запроса форма сохраняет введённый текст для исправления или повтора.

## Risks / Trade-offs

- [Своя клавиатура требует сопровождения фокуса и доступности] → Общий компонент; widget-тесты каретки, выделения, закрытия и видимости; ручная проверка Android, iOS и мобильного web.
- [Рациональная арифметика может расходовать ресурсы на длинном вводе] → Ограничения длины/вложенности, сокращение дробей, контролируемые ошибки и тесты границ.
- [Существующее хранение `double` не представляет все суммы точно] → Точная арифметика до преобразования, проверка диапазона/копеек, общая сумма для preview и submit; миграция хранения не входит в задачу.
- [Новые правила округления меняют ввод с более чем двумя дробными знаками] → Итог явно показан до сохранения; тесты положительных и отрицательных половин копейки.
- [Телефонная компоновка меняется при повороте и resize] → Один владелец панели и фокуса; проверки обеих ориентаций и перехода на широкую компоновку.

## Migration Plan

Миграции данных и API не нужны. Поставить клиент с общим полем после прохождения Flutter-проверок и проверки клавиатуры на целевых поверхностях. Откат — предыдущая версия клиента; уже сохранённые числовые значения совместимы. Правила публикации релиза выполняются отдельно по явному запросу.
