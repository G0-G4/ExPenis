## Сквозной сценарий

`e2e/test_personal_greetings.py`: 1 passed в Chrome, два независимых browser context, viewport 390×844. Использованы отдельный backend на 8273, Flutter web на 8274 и временная БД `/tmp/expenis-greetings-e2e/greetings.db`; рабочая БД не изменялась.

Проверены реальная CLI → пользовательский API → Flutter: персональное назначение, показ в двух сессиях, закрытие и обновление второго клиента, повторное назначение того же текста, подтверждённая массовая замена, отсутствие блока на другой вкладке, подтверждённое удаление. Принудительный HTTP 503 для сообщения оставляет транзакции и кнопку добавления доступными. Скриншот финального положения вкладки просмотрен.

Для повторения нужны изолированные backend и web-клиент, использующие одну временную БД:

```bash
E2E_GREETING_DB_PATH=/tmp/expenis-greetings-e2e/greetings.db \
E2E_BASE_URL=http://127.0.0.1:8274 \
E2E_API_URL=http://127.0.0.1:8273 \
uv run --group e2e pytest e2e/test_personal_greetings.py --browser-channel chrome
```

Без `E2E_GREETING_DB_PATH` тест пропускается, чтобы операторская CLI случайно не изменила рабочую БД.
